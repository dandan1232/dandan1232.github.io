在 ARM64 + NVIDIA GB10 服务器上部署 Step1X-3D

发布于 2026-09-23 · AI Infra / 3D 生成

这份笔记记录一次已经完成的部署：在 NVIDIA GB10、ARM64 远程服务器上运行 StepFun 官方 Step1X-3D，并通过浏览器把输入图片生成几何模型和带纹理模型。

公开版说明：文中的 203.0.113.10、10.0.0.41、deploy、gpu-node、SSH 密钥名、端口和本机目录均为示例，不对应真实服务器。执行前请替换为自己的配置；不要把私钥、Token、密码或真实公网入口写入仓库。

记录时间：2026-09-23。最终验证：服务首页返回 HTTP 200，端到端生成几何 GLB 和纹理 GLB；公开部署优先推荐 SSH 隧道，若必须开放公网访问，应额外配置身份认证、HTTPS、反向代理和防火墙。

1. 最终架构

这次没有把所有软件都装到服务器宿主机，而是分成三层：

  1. Windows 本机负责 SSH、上传源码、建立端口隧道、开浏览器。
  2. 远程服务器宿主机保存模型、运行 Docker、提供 GPU。
  3. NVIDIA PyTorch 容器运行 Python/CUDA 扩展和 Gradio 服务。
Windows 本机
  | SSH 22：登录、上传、端口转发
  v
203.0.113.10 / gpu-node
  | Docker host network + --gpus all
  v
step1x3d-dev 容器
  | /workspace -> /home/deploy/step1x3d
  v
Step1X-3D Gradio 服务：0.0.0.0:7000

下面用 10.0.0.41:7000 -> 203.0.113.10:7001 表示一种示例端口映射；如需公网访问，请按云平台或机房规则配置，并先补齐认证、HTTPS 和防火墙。另一种更安全的访问链路是：Windows 127.0.0.1:7861 -> SSH 隧道 -> 服务器 127.0.0.1:7000。

3. 本机前置条件和 SSH 登录

需要 Windows PowerShell、OpenSSH、Git、scp、服务器账号和私钥。示例私钥位置是：

C:\Users\your-name\.ssh\id_ed25519_step1x3d

不要把私钥内容写进笔记、启动脚本或 Git 仓库，也不要上传到服务器。可先检查本机是否有文件：

Test-Path "$env:USERPROFILE\.ssh\id_ed25519_step1x3d"
ssh -V

SSH 登录命令：

ssh -i "$env:USERPROFILE\.ssh\id_ed25519_step1x3d" `
  -p 22 `
  deploy@203.0.113.10

第一次连接会询问主机指纹；确认是自己的服务器后输入 yes。登录后确认身份和 CPU 架构：

whoami
hostname
uname -m
uname -r
id

预期包含 deploy、gpu-node、aarch64。ARM64 很重要：一些 x86_64 的 CUDA/Python 预编译包不能直接用，后面需要从源码编译扩展。

如果看到 Permission denied (publickey)，通常是用了 SSH 默认密钥。如果默认密钥不匹配，应显式指定 id_ed25519_step1x3d，不能只写 ssh -p 22 ...。

4. 源码和模型为什么分开获取

本次部署有两个不同来源：

来源 用途 地址
ModelScope 模型权重和配置 https://www.modelscope.cn/models/stepfun-ai/Step1X-3D.git
StepFun GitHub 可运行源码，如 app.py 和推理模块 https://github.com/stepfun-ai/Step1X-3D.git

实际检查发现 ModelScope 仓库不是完整运行应用，没有 app.py 等完整推理入口；所以单独下载它不能启动服务。反过来，GitHub 源码也不包含全部模型权重。把源码和权重分开取得，才有完整的运行材料。

第一次克隆模型后，某些 .safetensors 文件只有一百多字节，文件头是：

version https://git-lfs.github.com/spec/v1

这是 Git LFS 指针，不是真正权重。要先安装 Git LFS，再执行 git lfs pull。

5. 获取、打包并上传源码

完整仓库带较多示例资源。本次在 Windows 使用 sparse checkout，只取运行必需的源码和 examples：

Set-Location D:\workspace

git clone --depth 1 --filter=blob:none --no-checkout `
  --branch main `
  https://github.com/stepfun-ai/Step1X-3D.git `
  Step1X-3D-transfer

Set-Location D:\workspace\Step1X-3D-transfer
git sparse-checkout init --no-cone
git sparse-checkout set `
  app.py `
  inference.py `
  requirements.txt `
  step1x3d_geometry `
  step1x3d_texture `
  examples
git checkout main

如果提示 .git/index.lock 存在，先确认没有另一个 Git 进程工作，再只处理这个明确的锁文件：

Remove-Item -Force -LiteralPath `
  D:\workspace\Step1X-3D-transfer\.git\index.lock
git checkout main

不要因此删除整个 .git 目录。打包时排除 Git 元数据：

Set-Location D:\workspace
tar -czf Step1X-3D-source.tar.gz `
  --exclude=.git `
  Step1X-3D-transfer
Get-Item .\Step1X-3D-source.tar.gz | Select-Object Name,Length

本次压缩包约 105 MB。上传到服务器：

scp -i "$env:USERPROFILE\.ssh\id_ed25519_step1x3d" `
  -P 22 `
  .\Step1X-3D-source.tar.gz `
  deploy@203.0.113.10:/home/deploy/step1x3d/src/

登录服务器后解压。下面假定目标目录尚不存在，若已存在先检查再处理，避免覆盖用户数据：

cd /home/deploy/step1x3d/src
tar -xzf Step1X-3D-source.tar.gz
mv Step1X-3D-transfer Step1X-3D

6. 创建 NVIDIA PyTorch 容器

使用 nvcr.nju.edu.cn/nvidia/pytorch:25.11-py3。保留镜像自带的 PyTorch 2.10 + CUDA 13，不为照抄旧 requirements 而降级；这对 GB10 兼容性更合适。

docker pull nvcr.nju.edu.cn/nvidia/pytorch:25.11-py3
docker run -d \
  --name step1x3d-dev \
  --gpus all \
  --network host \
  -v /home/deploy/step1x3d:/workspace \
  -w /workspace/src/Step1X-3D \
  nvcr.nju.edu.cn/nvidia/pytorch:25.11-py3 \
  sleep infinity

--gpus all 把 GPU 交给容器；--network host 让宿主可访问容器 7000；-v 将模型和代码保存在宿主机；sleep infinity 让容器保持运行。

docker ps --filter name=step1x3d-dev
docker exec step1x3d-dev python -c \
  "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.get_device_name(0))"

预期：PyTorch 2.10.0a0+b558c986e8.nv25.11、CUDA 13.0、GPU NVIDIA GB10。

7. 系统库和 Python 依赖

docker exec -it step1x3d-dev bash
apt-get update
apt-get install -y --no-install-recommends \
  libgl1 libegl1 libglib2.0-0 libopengl0 git-lfs
git lfs install --local

libopengl0 解决 PyMeshLab 的 libOpenGL.so.0 缺失。无界面网格处理仍会用到图形库。

先确认 torch，再安装依赖。不要执行会覆盖 torch/torchvision/torchaudio 的安装命令：

python -c "import torch; print(torch.__version__, torch.version.cuda)"
cd /workspace/src/Step1X-3D
grep -vE '^(cupy-cuda12x|git\+https://github.com/NVlabs/nvdiffrast|git\+https://github.com/facebookresearch/pytorch3d|deepspeed|sageattention|open3d|prodigyopt|spaces|tensorboardX)' \
  requirements.txt > /tmp/step1x3d-runtime.txt
python -m pip install --no-cache-dir -r /tmp/step1x3d-runtime.txt

官方 requirements 混有训练、实验和特定平台依赖，所以筛选后再安装。固定遇到兼容问题的版本：

python -m pip install --no-cache-dir \
  "wandb==0.18.6" "onnxruntime==1.21.0" "xatlas==0.0.10" \
  "numpy==1.26.4" "tifffile==2024.5.22" \
  "pydantic==2.10.6" "pydantic-core==2.27.2"

NumPy 2.x 与 Trimesh 4.3.2 有兼容问题，因此用 1.26.4。Gradio 5.5.0 配 Pydantic 2.12 曾导致首页 500，固定 2.10.6 后恢复。

官方写 cupy-cuda12x==13.4.1，但容器是 CUDA 13；CUDA 12 版会找不到 libnvrtc.so.12。改装 CUDA 13 版：

python -m pip install --no-cache-dir cupy-cuda13x==13.6.0
python -c "import cupy as cp; print(cp.cuda.runtime.runtimeGetVersion())"
python -m pip install --no-cache-dir iopath==0.1.10 portalocker==3.2.0

CuPy runtime 预期 13000。iopath 和 portalocker 是 PyTorch3D 的辅助依赖。

8. 编译 ARM64/CUDA 扩展

ARM64 上有些组件没有适用的预编译包。本次编译 nvdiffrast、pytorch3d、Step1X 的 custom_rasterizer 和 mesh_processor。MAX_JOBS=2 限制并行，减少内存压力。

cd /workspace/src
git clone --depth 1 https://github.com/NVlabs/nvdiffrast.git
cd /workspace/src/nvdiffrast
MAX_JOBS=2 python -m pip install --no-cache-dir --no-build-isolation .

cd /workspace/src
git clone --depth 1 --branch stable https://github.com/facebookresearch/pytorch3d.git
cd /workspace/src/pytorch3d
MAX_JOBS=2 python -m pip install --no-cache-dir --no-build-isolation .

再编译项目自带模块：

cd /workspace/src/Step1X-3D/step1x3d_texture/custom_rasterizer
MAX_JOBS=2 python -m pip install --no-cache-dir --no-build-isolation .
cd /workspace/src/Step1X-3D/step1x3d_texture/differentiable_renderer
MAX_JOBS=2 python -m pip install --no-cache-dir --no-build-isolation .

验证：

python -c "import custom_rasterizer_kernel, mesh_processor, nvdiffrast, pytorch3d; print('compiled_extensions=ok')"

失败时先核对 torch/CUDA、nvcc --version、gcc --version、iopath 和 portalocker，不要先替换 torch。

10. 源码本地路径适配

官方代码默认会按在线模型 ID 加载部分模型。国内节点为了减少运行时联网依赖，对本地源码做了小幅补丁。这些改动位于本地工作副本 D:\workspace\Step1X-3D-transfer，之后随源码包上传到了服务器。

10.1 app.py：本地 Step1X 主模型和 Gradio 文件白名单

在 app.py 里使用环境变量 STEP1X3D_MODEL_PATH，替代固定的 stepfun-ai/Step1X-3D；几何和纹理两个 pipeline 都使用这个路径。

另外 demo.launch() 增加：

allowed_paths=[os.path.abspath(args.cache_dir)]

否则模型即使已经把 GLB 写入 /workspace/cache，Gradio 也可能因安全路径限制拒绝把文件返回给页面，并报 InvalidPathError。

10.2 CLIP 和 DINOv2 本地路径

修改文件：

step1x3d_geometry/models/conditional_encoders/dinov2_clip_encoder.py
step1x3d_geometry/models/conditional_encoders/dinov2_encoder.py

增加环境变量 STEP1X3D_CLIP_MODEL、STEP1X3D_DINO_MODEL，让 Transformers 从磁盘目录加载 CLIP/DINO，而不是访问在线模型 ID。

10.3 SDXL、VAE 和 BiRefNet 本地路径

修改文件：

step1x3d_texture/pipelines/step1x_3d_texture_synthesis_pipeline.py

增加 STEP1X3D_SDXL_MODEL、STEP1X3D_VAE_MODEL、STEP1X3D_BIREFNET_MODEL，分别指向本地目录。

13. 公网访问与可选 SSH 隧道

下面用一组示例端口转发说明访问链路：

10.0.0.41:7000 -> 203.0.113.10:7001

若已按前述要求安全配置公网入口，可用下面的示例命令验证；203.0.113.10 是文档保留地址，必须替换：

curl.exe --noproxy "*" http://203.0.113.10:7001/
curl.exe --noproxy "*" http://203.0.113.10:7001/config

如果不希望直接使用公网转发，也可以建立 SSH 隧道。

在 Windows PowerShell 执行：

ssh -f -N `
  -o BatchMode=yes `
  -o ExitOnForwardFailure=yes `
  -o ServerAliveInterval=30 `
  -i "$env:USERPROFILE\.ssh\id_ed25519_step1x3d" `
  -p 22 `
  -L 7861:127.0.0.1:7000 `
  deploy@203.0.113.10

参数含义：

  • -f：认证成功后转入后台。
  • -N：只做端口转发，不启动远程 shell。
  • -L 7861:127.0.0.1:7000：将本机 7861 转到服务器 7000。
  • ServerAliveInterval=30：定期发送保活包。
  • ExitOnForwardFailure=yes：端口转发失败时直接报错。

检查本机端口：

Get-NetTCPConnection -LocalPort 7861 -ErrorAction SilentlyContinue

现在浏览器打开 http://127.0.0.1:7861。如果 Windows/浏览器设置了 HTTP 代理，代理可能错误地拦截 localhost 并返回 502。绕过代理测试：

curl.exe --noproxy "*" http://127.0.0.1:7861/

若命令行 HTTP 200、浏览器却 502，服务和 SSH 隧道通常是通的；把 localhost、127.0.0.1 加入代理绕过名单，或临时关闭浏览器代理。

14. 故障排查记录

现象 原因 处理
Permission denied (publickey) SSH 自动用了默认密钥 明确指定 id_ed25519_step1x3d，检查用户名和端口
safetensors 只有约 130 字节 文件是 Git LFS 指针 安装 git-lfs 并执行 git lfs pull
libOpenGL.so.0 找不到 容器缺 OpenGL 系统库 apt-get install libopengl0
缺 wandb、onnxruntime、xatlas 运行依赖不全 按上面固定版本补装
ARM64 找不到 CUDA wheel 没有适用的预编译包 在当前容器里从源码编译，MAX_JOBS=2
libnvrtc.so.12 找不到 装了 CUDA 12 CuPy，容器是 CUDA 13 换 cupy-cuda13x==13.6.0
Gradio 首页 500 Pydantic 版本组合不兼容 固定 pydantic==2.10.6 和 pydantic-core==2.27.2
Trimesh/数组报错 NumPy 2.x 与旧 Trimesh 不兼容 固定 numpy==1.26.4
BiRefNet 配置/模型类错误 拿到训练项目格式，不是 Transformers 发布格式 用 ZhengPeng7/BiRefNet 发布版
找不到 u2net.onnx rembg 文件不在容器默认目录 放入 /root/.u2net/u2net.onnx
生成了 GLB 但页面 InvalidPathError Gradio 不允许返回 cache 路径 demo.launch() 加 allowed_paths
公网 IP:7861 返回 502 7861 没有平台端口映射 使用 203.0.113.10:7001，它会转发到服务器 7000
服务器 curl 200、本机浏览器 502 本机代理拦截 localhost curl 使用 --noproxy "*"，配置代理绕过

18. 页面生成参数说明

第一次使用时，推荐先保持官方页面默认值：

Guidance Scale：7.5
Inference Steps：50
Max Face Num：400000
Symmetry Type：根据物体选择
Edge Type：根据物体选择

这些参数主要控制几何模型的生成，不直接决定贴图分辨率。

参数 作用 调高或改变后的影响
Guidance Scale 模型有多严格地参考输入图片 越高越贴近图片，但过高可能产生畸形或僵硬细节
Inference Steps 扩散模型进行去噪生成的步骤数 越高通常越细致、越慢，超过一定数量后提升变小
Max Face Num 最终网格允许保留的最大三角面数 越高模型越重，文件越大，纹理和预览越慢
Symmetry Type 是否倾向生成左右对称的结构 x 为 X 方向对称，asymmetry 不强求对称
Edge Type 控制生成几何的边缘风格 sharp 硬朗，normal 折中，smooth 圆润

18.1 Guidance Scale

可以理解为“图片引导强度”。它决定模型生成 3D 形状时，多大程度遵从输入图片。

  • 数值较低：模型发挥空间较大，但生成结果可能不像原图。
  • 数值较高：模型会更努力贴近原图的轮廓和结构。
  • 数值过高：不一定更好，可能放大错误轮廓，产生奇怪凸起或僵硬结构。

推荐范围：

普通情况：7.5
结果不太像原图：8～9
出现畸形或奇怪细节：降到 5～7

官方示例和当前页面默认都是 7.5。源码中大于 1 时会启用 Classifier-Free Guidance，也就是把“没有图片条件”和“有图片条件”的预测进行组合，从而增强输入图片对结果的影响。

18.2 Inference Steps

页面当前写成了 Inferece Steps，这是拼写错误，正确名称是 Inference Steps，中文可以理解为“推理步数”或“去噪步数”。

  • 步数少：生成更快，但几何可能粗糙或不稳定。
  • 步数多：通常结构更完整，但耗时更长。
  • 步数翻倍不代表质量翻倍，后期提升会逐渐变小。

页面允许 1～100，默认 50。建议：

快速测试：20～30
正式生成：50
复杂物体：60～75
一般不必长期使用：80～100

实用做法是先用 25～30 步判断主体形状，方向正确后再用 50 步正式生成。

18.3 Max Face Num

表示最终网格允许保留的最大三角面数量。3D 模型的表面由大量三角形组成，例如 400000 表示最多保留约 40 万个三角面。

面数越高：

  • 可以保留更多几何细节。
  • GLB 文件会更大。
  • 浏览器预览更吃性能。
  • 后续纹理生成和网格处理更慢。
  • 内存和显存占用可能增加。

它只是减面时的上限，不是细节生成开关。原始生成分辨率有限，因此把数字无限调高不会凭空增加真实细节。

推荐：

快速测试、简单物体：100000～200000
普通模型：200000～400000
复杂雕塑或高细节物体：400000

如果最终模型要用于网页、游戏或移动设备，通常还需要在生成后继续减面和优化纹理。

18.4 Symmetry Type

这是 Label 版几何模型的条件参数，用来提示模型是否生成对称结构。它是生成引导，不是建模软件中的严格镜像修改器，不能保证每个顶点完全对称。

x

倾向按 X 方向左右对称，可以理解为关于模型中间的 X=0 平面对称。

适合：

  • 人脸、正面站立的人物
  • 汽车、飞机、机器人
  • 椅子、瓶子
  • 大多数正面拍摄、左右结构一致的产品或动物

asymmetry

表示不强求左右对称。

适合：

  • 人物摆出不对称动作
  • 单肩包、茶壶把手等单侧结构
  • 一边有特殊装饰的物体
  • 不规则石头、植物
  • 输入图片本身明显左右不同

如果原物体明显不对称却选择 x，模型可能把单侧结构复制到另一侧，或者忽略不对称特征。

18.5 Edge Type

这是 Label 版几何模型的另一个条件参数，用来提示模型采用哪种边缘风格。

sharp

强调硬边、折角和平面结构。适合机械零件、家具、汽车、电子产品、建筑、箱子和卡通硬表面道具。当前页面默认值是 sharp。

normal

普通、折中的边缘风格，不特别强调硬边或圆润。适合同时包含硬边和圆角的日常用品、鞋子和玩具。不确定如何选择时，可以先用 normal。

smooth

倾向生成圆润、连续的曲面。适合人物、动物、毛绒玩具、食物、石头、有机体和雕塑。

机械物体选择 smooth 可能使边角变钝；人物或动物选择 sharp，表面可能出现不自然的折面。

18.6 推荐参数组合

普通产品或不确定如何选择：

Guidance Scale：7.5
Inference Steps：50
Max Face Num：400000
Symmetry：根据图片决定
Edge Type：normal

汽车、机器人、家具等硬表面物体：

Guidance Scale：7.5
Inference Steps：50
Max Face Num：400000
Symmetry：x
Edge Type：sharp

人物、动物、毛绒玩具：

Guidance Scale：7～7.5
Inference Steps：50
Max Face Num：300000～400000
Symmetry：正面且左右一致选 x，动作不对称选 asymmetry
Edge Type：smooth

快速试生成：

Guidance Scale：7.5
Inference Steps：25～30
Max Face Num：150000～200000
Symmetry：根据物体决定
Edge Type：根据物体决定

最重要的是根据输入物体选择 Symmetry Type 和 Edge Type。其余参数先保持默认，看到具体问题后再调整，通常比一次把数值全部调高更稳定。
